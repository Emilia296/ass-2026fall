# 轻量业务 Agent

本实现是**面向充电业务的受控工具编排 Agent**：识别有限范围的中文意图，检查权限，调用真实数据库查询工具，将结果组织为回答，同时返回可核对的数据、来源接口和时间。无需模型服务、API Key、向量数据库或新增业务表。

答辩可表述为：**实现了业务数据驱动的轻量 Agent，支持自然语言业务查询、多工具运营报告、权限隔离和可追溯回答。** 实际引擎明确为 `RULE_BASED_TOOL_AGENT`，不宣称使用大模型、通用推理、RAG或自主设备控制。

## 接口与演示

新增 `POST /api/v1/app/agent/chat` 和 `POST /api/v1/admin/agent/chat`，使用对应端的 Bearer Token；Swagger 可直接调试。统一响应的 `data` 包含 `engine`、`status`、`answer`、`toolCalls`、`asOf`、`limitations`，运营查询另含 `period`。每个工具返回 `tool`、`source`（对应业务查询入口）、`data`。来源入口用于核对，不代表Agent实际发起了内部HTTP请求。

请求示例：

```json
{"message":"附近空闲快充站","longitude":116.51,"latitude":39.92}
```

| 端 | message 示例 | 实际行为 |
| --- | --- | --- |
| 用户 | 附近空闲快充站 | 10公里内按距离返回最多3个营业且有空闲快充桩的站点；缺位置返回追问 |
| 用户 | 当前充电费用 | 查询本人未离场会话及实时预估费用 |
| 用户 | 当前电价 | 返回当前会话锁定费率在当前时段的电价、服务费 |
| 用户 | 最近一次订单 | 本人最近订单金额、用电量、支付状态；应付金额不冒充实付 |
| 用户 | 充电异常 | 联查本人会话和当前设备状态，给出反馈建议，不推断未经证实的故障原因 |
| 运营 | 今日站点订单排名 | 今日订单最多的前5个站点 |
| 运营 | 近一周营收 | 成功支付减成功退款，复用运营仪表盘口径 |
| 运营 | 故障设备排行 | 统计期内故障记录次数前5名，不等同于设备故障率 |
| 运营 | 近一周运营报告 | 一次编排营收/用户/设备汇总、站点订单排名、故障排名3个工具 |

运营统计支持“今日/今天”，否则默认最近7个自然日（含今天）；不解析任意日期。报告需同时拥有 dashboard、order、station、fault、pile、user 的查看权限，所有权限在执行前统一检查。维修员可以查询故障排行，不能借报告获取订单和用户统计。营收单项沿用仪表盘查看权限。

## 实现边界

- 只读工具白名单，没有任意SQL、代码执行、支付、预约或设备控制；用户身份只取登录令牌。运营请求沿用审计日志。
- 每账号每分钟30次，单条问题1至500字，单次最多3个工具；不保存会话，不支持跨轮指代。无需新增外部依赖。
- 未接入餐饮地图，餐厅问题明确返回 `unsupported`；无业务数据明确返回空结果，不生成假记录。
- 关键词路由支持上表代表性问题，复杂表达和混合意图不保证正确理解。用户端优先识别附近站点、历史订单、当前会话；运营端可组合多项查询。
- 工具数据来自请求期间的实时查询，不保证多条SQL处于同一业务快照；费用和空闲状态可能随后变化。没有独立压力测试或已完成公测的性能结论。
- 前端本轮未接入。演示建议按“附近站点→当前费用→最近订单→运营报告→维修员越权被拒绝”顺序操作；当前费用需先创建充电会话，最近订单需先结束并离场。
