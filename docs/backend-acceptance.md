- 用户、车辆、站点、收藏、空闲提醒、预约、充电计费、订单、模拟支付、优惠券、积分信誉、消息、售后退款、故障运维、RBAC、审计和配置。

实际 HTTP 联调中，通过独立模拟器、Redis入队和Worker消费读取到增长的充电量，随后成功停止、驶离、生成订单和模拟支付。联调为演示账号留下两笔已支付订单，没有生成批量负载。

自动化测试覆盖：

- 充电—订单—优惠券—支付—部分退款，重复支付/驶离/退款处理。
- 两个用户争同一桩、同一用户争多个桩、两个支付请求、最后一张券的争抢。每个竞争场景只有两个并发请求，用于验证正确性，不是压力测试。
- 预约确认到场并充电、爽约释放设备及扣分一次性执行。
- 订单逾期扣分一次性执行；正常充电奖励与异常充电不奖励。
- 跨电价时段、跨午夜、占桩30/60分钟边界、封顶、目标电量停止及明细分币舍入。
- 密码连续失败锁定、人工解锁、旧Token失效、对象归属、运维角色权限隔离、修改角色权限后立即生效。
- 动态价格快照、后台实体新增修改、积分信誉调整、故障接单处理、每日赠券次数、消息软删除。
- 设备签名、重复上报、pending消息认领恢复、坏消息死信处理、设备故障异常停止。
- 请求参数、路径ID、错误响应结构、时间范围及手机号筛选。

测试使用 `charge_test` 和 Redis DB 15，演示库 `charge` 未被测试清空。最终完整测试运行出现1条第三方 Starlette/AnyIO 的 `BlockingPortal` 弃用提示，无测试失败。运行观察中 Worker 出现过瞬时 Redis 读超时，重试后恢复，后续真实设备链路及支付均成功；异常处理不会 ACK 未提交的数据。
